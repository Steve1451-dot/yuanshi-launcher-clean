# 0.2.93：每游戏手柄映射与可选体感辅助

本版新增本地手柄配置界面和 SD 持久化。不是“安卓原生体感已经修好”的版本，
也没有把 Switch 的硬件信息伪造成手机。登录、派发、解码、音频与网络参数未修改。

## 使用

进入游戏后，触摸悬浮球 → **手柄自定义映射**。

- 第 1、2 页选择实体按键，再选择要发送的游戏按键；可禁用，可将多个键映射到同一目标。
- 点击“上一页 / 下一页”或用方向键＋A 操作，B 返回上一级。界面仍使用原来的深色青色风格。
- 修改成功保存到 SD 后立即生效，下次启动自动恢复，原神、星铁、绝区零、终末地互不影响。
- 目标 A/B/X/Y 是最终虚拟手柄的名称；Endfield 会跟随原有 Xbox/Switch 布局选择。
  原神原有 AB/XY 互换作为默认值保留，因此原神默认页面可显示“实体 A → 游戏 A”。
- 减号是本地诊断保留键，不提供重映射；其他键可以映射为远端 Back。
  本地菜单的 A/B、诊断/退出组合键和已有悬浮窗手势不改。
- 恢复本游戏默认配置需两次明确选择；不会清除别的游戏、账号或画质设置。
- 日志导出仍在“串流诊断”中；主悬浮菜单原来的重复导出入口换成了按键设置入口。

该界面提供数字按键/扳机/摇杆按压的映射，不提供宏、连发、摇杆轴互换或游戏内功能名称编辑。
模拟器/云端游戏内部的设置界面不是本地映射界面，两者不要混淆。

配置位置由 `AppHomePath()` 派生，当前为：

```
/switch/SwitchNOW/controller-mapping-hk4e.txt
/switch/SwitchNOW/controller-mapping-hkrpg.txt
/switch/SwitchNOW/controller-mapping-nap.txt
/switch/SwitchNOW/controller-mapping-endfield.txt
```

仅含版本、游戏键和映射/体感选项，没有账号或令牌。
检查文件长度、版本、游戏、所有目标和参数范围；损坏时尝试 `.bak`，否则回退该游戏默认配置。
临时文件关闭并检查写入后才原子替换。保存失败时当前映射也保持不变，并显示中文错误。
不逐帧写 SD、不新增输入线程；变更时沿用现有中立帧/输入代次和松键门禁，避免卡键。

## 原神体感辅助

按键界面的第 3 页提供 **体感转右摇杆（实验）**，默认关闭，且只在原神可开启。

- 开启后默认按住游戏 LT（未改映射时通常为实体 ZL）才有体感瞄准。
- 支持始终启用、50/100/150/200% 灵敏度、独立反转横轴和纵轴，均随本游戏保存。
- 使用最新角速度生成虚拟手柄右摇杆。物理右摇杆的明确操作优先，不改变左摇杆、按钮或扳机。
- 面板/退出/输入交接、传感器无效、时间异常、超过 100 ms、手柄通道未就绪时不生成体感摇杆。
- 开启本地辅助后不同时发原生 IMU，避免以后云端激活时出现双重控制；关闭后恢复原来的云端开关门禁。

**这是本地兼容方式，不是安卓原生 IMU、姿态四元数透传成功或游戏内原生体感已验收。**
坐标换算有独立测试，但真实握持方向、瞄准手感和长时漂移仍需真实 Joy-Con 与游戏验收。
新增诊断 `GYRO_STICK_ASSIST_FRAMES_SENT` 只表示本地通道接受体感转摇杆后的手柄帧，非云端 ACK。

## “包装成手机”核查

用户的方向有技术依据，但目前只能认定存在协议路径差异，不能认定改变身份就一定解决：

1. APK 协议枚举中 `CTT_ANDROID=3`，当前默认 `CTT_WEB_KEYBOARD=10`。
   现有 `cloudgenshin-terminal.txt` 只覆盖串流阶段的 StartGame/SdkDeviceInfo、启动指针和桥 CPS；
   前面的网页身份与请求构造没有同步切成完整安卓实现。
2. `NativeWebIdentity`、`BuildPrepareRequest` 的测速 platform=19 和 `LaunchFlow` 的设备信息仍是
   现有网页/真实 Switch 路径。因此只改终端文件或 UA 不能称作“全安卓移植”。本版未改这些请求。
3. 原版 `ClientCore.onImuActivationChanged` 只在云端通知开启且应用允许传感器后调用
   `mImuEventListener.start()`；`MihoyoSdkHolder.isImuSensorEnabled` 读取 `mi_cloud_open_sensor`。
   这不是客户端开机就不受条件地发送全部六轴。
4. `BaseSdkHolder` 中 `cloud_set_sensor_level` 是按游戏请求选择参数并调用
   `setCustomSensorParameter(x,y)`，不是“打开 IMU”报文；该版本静态 `MihoyoSdkHolder` 的
   `openSensor` 和 `setCustomSensorParameter` 默认无操作（运行时热补丁可能改变），不能据此虚构开启协议。
5. 上次实机是新鲜采样/有效姿态为 1，而识别到的云端开启请求和原生发送数为 0。
   这指向“原生激活/适配未打通”，不是已经证明编码发送失败，也不是证明游戏一定支持当前终端。

下一步需要受控验证完整安卓请求参数与游戏模式，并观察云端原生激活及游戏实际采用，
而不是把硬件设备名改成某款手机，或把日志里的开启状态强行设成 1。
未加入虚假的指纹、未知协议字段或取消认证/TLS 检查。

本版补充安全计数：

- `MOTION_FEEDBACK_RECEIVED`：有效原生开关回包，包括合法关闭请求。
- `MOTION_FEEDBACK_INVALID`：识别为 type 23 但校验不通过的回包。
- `MOTION_FEEDBACK_BEFORE_AUTH`：会话未就绪时收到并忽略的开关。
- `MOTION_NATIVE_ANDROID_ROUTE_SELECTED/NOT_SELECTED`：当前串流终端路径，不表示体感生效。

保留采样、姿态、原生发送与失败计数。按约 5 秒汇总，不记录报文内容、原始姿态、账号信息或逐采样日志。

## 本轮验证

20 项不同的相关主机测试通过：映射全部 65536 个按键掩码与旧默认的真实 wire 一致性、
全部源/目标、重复目标、禁用、文件隔离与重读、损坏/超长/错游戏/备份恢复、失败不覆盖；
编辑器触摸/手柄边沿、换输入源、恢复确认、保存失败、分页面和游戏范围；
中英两种语言/所有游戏的绘制命令模型；体感轴向、反转、静止噪声、过期、手柄覆盖和限幅；
原有六轴/四元数、真实 Session 的离线 RTC/WebSocket 模型、输入捕获/交接、Endfield XInput、
SDK 桥和安全日志回归。绘制命令模型不是屏幕截图或实机视觉验收。

生产 Switch 构建通过（首轮 125 步，最后改动后 14 步增量构建），版本检查为 0.2.93。
只见原有第三方 stb 的初始化警告，没有修改第三方代码。
