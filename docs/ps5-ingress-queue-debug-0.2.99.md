## 已确认的排队错误（0.2.99 修正）

APK 7.1.0 `DispatchQueueInfo.java` 分别定义 `queue_rank`、`queue_length`、
`branch_queue_len`。`M4/n.java:116` 和 `L4/v.java:395` 将 rank 与 length
分别交给 EnqueueService；`L4/DialogC1081g.java` 的排队显示也读取 rank。

旧客户端只解析 `branch_queue_len`，却将它发布为 `QUEUED_POSITION`，
参与前方人数显示、速度估算和“超过100自动退出”。因此此前日志出现400多，
**不能据此说我们排在400多位**；也不能凭它断言当前没有人在排队。
这是可确认的字段映射错误，不是证书过期或扫码失效。

- .99 独立解析三项可选数字，支持整型与十进制字符串，检查负值、类型和溢出。
- `QUEUED_POSITION` 只使用 `queue_rank`；缺失或非法时为未知（-1），
  首页显示 `--`，清除旧位置样本与估算，不退回总长度充当排名。
- 仍保留用户要求的个人位置超过100默认退出；个人位置未知不触发此规则，
  仍受取消和既有等待期限控制。不会升级付费、换节点重排或重放派发。
- 安全日志新增 `QUEUE_TOTAL_LENGTH` / `QUEUE_BRANCH_LENGTH`，中文注明
  “不是个人位置”。这些纯诊断事件不覆盖界面状态或重置排队估算。
- 历史 .98 及以前的 `QUEUED_POSITION` 不能追溯当成个人排名。测试脚本
  对这些版本改用 `UnverifiedQueueCounter` 标签，保留原日志作为历史证据。

## 0.2.97 媒体入口修正与证据

- 生产 libpeer 的接收 payload 更新原先拒绝 COMPLETED 状态，而上层允许
  同一 ICE/DTLS 传输上的 connected reoffer。现在允许该状态更新音视频PT，
  仍拒绝失败/关闭状态、非法PT和不支持的重协商。未放松证书或SRTP校验。
- 最近RTP类型独立缓存，避免后续DTLS/RTCP覆盖接收缓冲而污染诊断。
- 增加经过SRTP验证后的类型拒绝、SSRC拒绝、音频/视频路由计数，保留最近
  SRTP/SRTCP错误。受既有5秒统计和关键阶段快照节流，没有逐包日志。
- Genshin与Endfield共用数字入口统计；20秒首帧前分类可区分解密、类型、
  SSRC拒绝、仅音频、视频未组帧/未解码。分类非致命，不缩短120秒媒体等待。
- RTP形状计数不是认证成功，也不能由零计数推断远端完全没发送任何UDP。
  路由计数不是解码成功，提交渲染也不是实际画面或游戏按键响应的证明。

实际 libpeer 传输测试覆盖完成后的PT更新、后续收包、非法状态/编号、
SRTP解密失败不解码、类型/SSRC拒绝及DTLS/RTCP不污染最近RTP编号。
Session合成替身同步收紧，避免之前“总返回成功”掩盖生产库限制。
