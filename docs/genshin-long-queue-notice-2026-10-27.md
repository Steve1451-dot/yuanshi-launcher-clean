## 本次实机日志的原因

用户提供的 0.2.83 安全日志显示：保存登录验证 HTTP 200；重新扫码后也有
LOGIN_OK HTTP 200。几次派发均已进入普通队列，人数分别为 243、243、233、327，
随后立即出现 QUEUE_ABANDONED_TOO_LONG 和 QUEUE_LEFT HTTP 200。

这是客户端已有的“前方超过 100 人自动退队”规则，不是本次证书或二维码到期。
终末地先前修过的是授权失败未显示，不能把两次现象当成同一个服务器错误。
本轮只读取安全日志，没有读取、解密、修改或打包用户的 key/vault。

用户最后明确要求保留默认退出，只增加提示框；因此最终版本没有取消这个规则。

## 改动

- 前方超过 100 人仍自动退出普通队列；100 人及以下继续原流程。
- 退出后弹出一次中英双语提示：实际排队人数、本客户端 100 人默认上限、
  登录仍保留、无需重新扫码。单个“知道了”按钮，B 也可以关闭。
- 弹窗只在 UI 线程、启动 worker 和退队请求结束后打开。每次启动最多一次；
  新尝试清空旧提示，不在 draw 循环重复弹窗，也不从网络线程操作界面。
- 服务器确认退队成功才说“已退出”；退队请求失败则明确说“本机已停止等待，
  服务器退队尚未确认”。不把本地停止等同于云端确认。
- QUEUE_LEFT / QUEUE_LEAVE_FAILED 仍写入安全日志，但不覆盖首页真正的退出/
  失败原因。首页持续显示“排队人数过多”，不再只剩“已取消”。
- 派发网络/HTTP/格式错误显示具体中文阶段和数字码，不回落成“已登录”。
- 原有两小时截止、手动取消、只读 Poll 有界重试、单次初始分配和 ACK 保留。
  不升级付费队列，不自动重新排队，不更换账号或弱化证书校验。

本轮未修改解码、媒体调度、音频或自动日志容量；保留 0.2.83 的既有改动，
不声称硬解黑屏、流畅度或所有断线恢复已经通过实机验收。
