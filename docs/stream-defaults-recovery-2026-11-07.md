# 保存偏好、最高画质默认值和共同恢复修正

## 启动优先级

原神和 zmd 均优先恢复当前应用目录内、各自上次保存的手动画质和帧率。
没有有效保存记录时，默认最高画质（6000–12000 kbps 请求范围）、60 FPS。
旧的有效“两整数”设置也按原值恢复，不再被强制改成省流 / 60 FPS。
已使用的带标记文件格式和备份恢复方式保持兼容，不读取旧应用目录。

保存记录在申请云端实例前即进入调度参数，首帧后的画质、帧率请求也使用
同一偏好。弱网自动降帧和降码率仍只作用于当前会话，不覆盖手动偏好。
Switch 显示分辨率继续为 1280×720，当前支持的最高请求帧率为 60 FPS。

## 本次实机日志依据

通过用户提供的 FTP 只读取得最近 zmd 安全性能日志，未下载账号文件或修改
设备文件。会话末段累计记录 75 次画面恢复、687 帧关键帧等待丢弃、28 次
解码队列拥塞、1056 次音频输出丢弃和 111 次音频断流。平均解码耗时约
4.9 ms，收包阶段最高约 529 ms，关键帧恢复最长约 2.3 s。历史最大耗时
不能定位每次卡顿的具体原因，也不能单独归因于网络带宽或解码性能。

同一会话中，服务端码率反馈明确出现 4000、8000、12000 kbps，并有后续
自动降低记录。因此本次日志不支持“省流与高清实际下发了同一个上限”的
判断；两档实测接收码率相近，也可能是场景编码需求或流畅保护的结果。

这次修正在共用的关键帧策略、弱网策略和音频模块完成，两种游戏都使用，
不修改第三方代码或绕过受损参考帧的恢复。细节见
`weak-network-streaming-2026-11-07.md`。日志和下载的运行数据仅存于被 Git
忽略的本地构建目录；测试使用独立合成数据。

完整 Switch 构建和相关主机回归用于验证实现。修正后的持续游戏、无线抖动
和音画体验仍需使用新 NRO 实机复测，不能从这些检查推断实机卡顿已经消失。
