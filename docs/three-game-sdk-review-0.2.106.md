# 0.2.106：共用成熟管线，分开核对崩铁授权

日期：2026-11-03，Asia/Singapore。不是崩铁入场错误已解决的声明。

## 三个游戏的进度

- 原神：保留用户已验证的可玩基线、Xbox、本地映射、ZL 体感、透明状态窗、
  触摸菜单、减号地图和软硬解码回退。新增保存登录再验证与服务检查网络原因。
  本轮没有重跑原神线上或真实 Switch 长时间测试，不能称为百分百稳定。
- 终末地：继续使用原有独立授权协议与共用音视频组件。本轮没有改变其协议、
  手柄和画质配置，也没有新做实机验收。
- 崩铁：现有加密登录可以在 Combo 失效时重新验证，无需再扫码；普通派发、
  WebRTC、真实视频和音频已经在 yuzu 中运行。但点击进入仍出现游戏内登录
  异常，图中错误为换行显示的 `1001_2`；新一轮遥测也取得数值返回码 `1001`。
  尚未证明进入游戏世界，更没有完成真实 Switch 性能验收。

共用的是成熟的串流、解码、渲染、输入和菜单，不是把不同服务的账号协议强行
当成一样。崩铁自己的游戏内登录返回值仍须与官方实现逐项对齐。

## 已验证的保存登录修复

`ResumeLogin` 原先在官方云端返回 `TOKEN_INVALID=-100` 时直接拒绝保存登录。
现增加可选输出：只有存在已授权账号凭据，且调用者能接收替换授权，才执行
一次官方原生 Account → Combo 交换，再校验一次云端登录。

- 账号、游戏、渠道和 open_id 必须一致；只在校验成功后交给原有原子加密存储。
- 不改变 vault 格式，不输出、解密导出或复制凭据到发布包。
- 风控、验证、资格拒绝、网络异常不进入自动刷新循环；失败不覆盖原登录。
- HTTP、网络或不完整响应允许稍后重试，不误删账号或自动弹出新二维码。
- 后台恢复与手动开始均保存成功刷新的结果；不重复派发，不使用付费队列。

同一隔离测试环境中，0.2.105 在保存登录验证返回 -100；0.2.106 随后在原有
加密凭据基础上取得真实云端授权并进入串流，全程没有重新扫码。这是具体改善，
但它解决的是“云端登录恢复”，不是已解决崩铁“游戏内登录”。

## 崩铁参数对照与无效假设的隔离

本地官方参考：`reference/web/sr/combo-web.7d4a7ffa.js` 与 Android 4.6.0 的
`PlatformHandler.java`、`ComboLoginManager.java`、`UserData.java`。

H5 `_createComboLoginSuccResult` 在合并返回字段前去掉宿主的 heartbeat、
fatigue_remind 和 data 包装，再展开内部 data。现对 app_id=8 的桥回包去除
原有 heartbeat/fatigue_remind；原神和绝区零既有行为不改。该调整没有在联机中
消除崩铁错误，不能当作根因修复。

另验证了“游戏内授权太旧”的假设：官方 H5 在游戏请求登录时重新申请 Combo；
原生此前只复用排队前授权。试验在派发后、RTC 启动前执行一次官方原生 Combo
交换，独立供 SDK 回包使用，不改云端授权和 vault。新授权成功取得，但仍然
出现 1001_2。原生 v2/login 不是 H5 webLogin，不能声称二者已经完全等同。

这个无效于当前错误的试验已隔离：仅同时具有普通自动测试开关、崩铁专用精确
标记、且在自动测试串流中才可启用。正常启动不新增该请求。标题指针点击也
仅保留为独立诊断选项，不据此修改用户的默认游戏内手柄策略。

没有伪造 Cookie、mid 或服务指纹，没有关闭 TLS 验证；没有把 Android 身份、
Xbox 身份、终端类型、CPS 与解码器同时更改来混淆测试变量。

## 每轮测试留下可用证据

- 崩铁诊断遥测预算由 24 增至 64，仍有固定上限，仅在显式追踪时记录字段名
  和允许的整数错误码，不保存正文或字段值。
- 一般运行只额外记录一次崩铁游戏遥测的首个非零 retcode；与 `1001_2`
  精确文本标记分开，不能从数值 1001 猜出完整 UI 文本。
- 监控报告跨有界日志淘汰保留这类证据；测试正常结束、有画面、音频提交或
  场景亮度变化，都不再被提升为进入游戏的证明。
- 自动测试的灰度游戏画面由 480×270 改为 960×540，最多 12 张，用来辨认
  换行错误码。只抓已解码游戏帧，不抓登录界面、桌面或二维码。
- 内层遥测与缓存 schema 的字符串 JSON 也使用有界解析，拒绝过深结构。
- 最终复测曾在服务检查阶段提前失败，HTTP=0，旧处理把异常原因丢成 retcode=0。
  现保留整数 CURL 错误码及准备阶段；不记录异常正文，不加自动重试、跳过
  证书校验或重复派发。此前这一次的确切网络原因不能由 0 倒推出超时。
- 又复现了自动测试交接竞态：UI 已读取本帧的启动参数快照后，工作线程结束，
  同帧轮询读取更新后的空闲状态，误报整个启动测试结束。测试器据此提前关闭
  yuzu，甚至没有等到第一帧。现保留本帧原先的忙状态，下一帧正常接收串流；
  监控端也兼容旧 NRO：见到成功派发交接就不把 launcher-finished 当作串流
  结束，必须等待真正的串流结束标记。失败和超长队列退出仍保持原语义。
