# 0.2.107：移除绝区零，继续对齐崩铁

日期：2026-11-03（Asia/Singapore）。崩铁仍未完成入场验收，不能称为已修好。

## 仅保留三个游戏

首页只保留原神、崩铁和终末地。绝区零的可选 profile、服务地址和应用常量、
翻译名称、映射入口、独立画质路径和背景生成项均移除；旧选择值 nap 安全回到
原神。其他游戏的背景仍使用原文件名，终末地不会误用其他图片。

没有删除用户的 SD 数据。旧 vault 若同时含绝区零和原神登录，不能因绝区零
不再受支持而整库判坏：现将这一旧条目仅作不参与登录的加密兼容数据保留。
读取和保存其他游戏仍可用，新建绝区零授权被拒绝。测试用真实 AES-GCM 的
合成混合登录库证明保存崩铁后原神和原绝区零条目都保留，未知游戏仍不接受。

## 崩铁的具体修改

### 1. 标题进入改为共用指针路径

此前 .106 对照中，反复发送 XInput A 停在标题，指针点击能触发实际登录请求。
移除崩铁标题页的特殊 gamepad-only 策略：手柄面键快捷进入、Continue 和有界
自动进入均走标题指针；SDK 入场之后仍是 Xbox 手柄，不继续注入标题点击。
未改变游戏内输入包、每游戏映射或原神物理 ZL 体感。原神已有路径保持等价。

这项依据是“可以触发标题登录”，不是“已经进入崩铁世界”。

### 2. H5 登录数据保留额外顶层字段

官方 `combo-web.7d4a7ffa.js` 的 `_createComboLoginSuccResult` 去掉宿主服务字段
heartbeat/fatigue_remind/data，再合并剩余顶层字段和内部 data。旧原生解析仅保留
四个顶层字段，会丢弃其他顶层扩展。

仅对 hkrpg 按该规则保留其余字段，并维持大小/深度限制、验证过的身份字段与
后合并覆盖顺序。原神的元数据处理不变。新增额外字段数量诊断，不记录名称
或内容；是否实际影响本次游戏错误，需要成功到达 SDK 的联机测试证明。
现有派发后重新获取游戏授权仍是独立测试开关，正常游戏不会新增该试验请求。

### 3. 不向崩铁填写本地伪指纹

同一官方 InfoModule 在没有宿主 device_fp 回调时返回空字符串。原实现即使
没有服务指纹，也会把本地 FNV 派生值返回游戏。本版崩铁改为空字符串，原神
保留旧行为，未伪装为已取得官方指纹或已通过风险认证。

这不证明官方宿主始终不提供回调，更不证明该差异就是 1001 的根因。

### 4. 安全网络文本线索

仅显式协议追踪时，从固定消息字段识别有限的 DNS、超时、TLS、连接失败和
HTTP 文本短语，输出整数位标记。它是“文本提及的线索”，不是确定原因。
不输出消息正文、URL 或账号内容；原有有界日志/监控仍区分游戏错误与 RTC 故障。

## 本轮联机结果

使用隔离 yuzu，已有加密登录，一次启动仅一次普通派发，不自动重放初次分配。

| 测试 | 实际停止点 | 可以得出的结论 |
|---|---|---|
| h5-fields-107 | 35 秒，DISPATCH_NETWORK_ERROR，CURL 28 | 保存登录恢复成功；未进入 RTC，未验证新 SDK 数据 |
| host-contract-107 | 37 秒，getNodesInfo 超时，准备阶段 3、CURL 28；测速 10/11 成功 | 保存登录恢复成功；仍未验证新的指纹回包和游戏入场 |

随后使用无账号的 Windows HTTP/1.1 对照：直连根路径 HTTP 405、TLS 校验 0、
约 0.60 秒；对只读节点接口空参数请求 HTTP 200、约 1.27 秒。这只能证明电脑
基础连通及接口能返回，不能证明带登录的 NRO 请求相同，也不能定位到账号、
网络或模拟器中的某一个原因。未关闭证书校验、伪造身份或连续重放派发。

此前 .106 的游戏内 1001 尚未在本次成功到达 SDK 后重测，因此不能把两次
前置超时称为 1001 已修复，也不能拿 .106 的画面当作本版在线验收。
