# 0.2.108：崩铁官方网页登录与可续期的登录保存

日期：2026-11-04（Asia/Singapore）。本版仍是候选，未完成崩铁游戏世界入场验收，
不能把保存登录成功或标题画面称为整个项目完成。

## 已修复

崩铁 Passport 的应用标识不再误用原神配置，按官方网页配置分别选择。Combo
app_id=8、云客户端类型 19、终端类型 10 和 Xbox 输入合同保持各自含义，未混用。

崩铁入口改用官方网页登录；手机确认后验证 SToken 的明确类型与同账号身份，
同时保留官方 MID，再获取真正的 Combo webLogin，最后验证云服务登录。
缺少网页上下文的旧登录显示“更新网页登录”，不静默删库或用旧凭据盲目排队。

新 MID 仅保存到原有 AES-GCM 加密登录库的可选字段，旧 v1/v2 兼容，写入仍是
原子替换。取消、验证拒绝或新登录失败不会覆盖原库；原神和终末地数据不清理。
过期网页授权只走同账号的正式续期；网络错误保留登录，不自动变换 token 类型、
身份或取消证书验证。

## 本轮实际验证

隔离 yuzu 取得官方二维码，用户手机确认后：

`PASSPORT_QR_CONFIRMED → PASSPORT_STOKEN_VERIFIED → LOGIN_OK → LOGIN_SAVED`

关闭并重新运行后，保存登录恢复成功，官方网页续期到阶段 4 成功，云服务验证
及再次加密保存成功。不需要这轮再扫二维码。这是实际联机结果，不是 mock。

第一轮正常进游戏测试在测速停止：11 个目标均连接超时，尚未派发。随后最终
诊断候选的对照中 11/11 测速成功、派发和 RTC 成功，实际显示开场动画；
73 秒游戏遥测返回 1001，画面明确显示 1001_2。101 秒主动停止时，1306 解码帧、
解码错误 0、4138 音频包，没有 SDK 入场信号。因此本版仍未修复该游戏内错误，
不能把它归结为二维码或宣称是用户的网络问题。
具体报告与每次候选的哈希在根目录 `outputs/star-rail-online-20261104`。

继续核对初始化发现此前指纹判断不完整：`ae.device_fp` 默认是读取 FP SDK 的
函数，`Ct._init` 会初始化该 SDK；只看 InfoModule 的无函数回退会漏掉这条线。
这证明原生分支尚未接入这一上游来源，不证明它就是 1001_2 的唯一根因。
0.2.109 将独立验证服务返回值到游戏 getter 的传递，0.2.108 二进制不覆盖。

## 网络定位补充

测速失败现在输出固定数字的首次失败阶段、耗时、端口、系统错误，以及 DNS、
TCP、TLS、传输就绪和总时间。它们是 curl 观察到的累计时间，不是完整网络抓包，
不证明哪一方有错；保留“未知”状态。不输出目标地址、会话 URL、响应或凭据。
HTTP 失败与 WSS 连接共用同一小型数字采集器，释放句柄前采集。

测速仍有目标数、并发数、每目标及总时限；本版没有伪造 RTT、绕过全部测速失败、
自动重放初次派发或改用付费队列。

## 三个游戏的边界

- 原神：保留现有输入映射、ZL 本地体感、媒体路径；登录库兼容和桥的回归测试
  通过，本轮没有新增真实 Switch 长时验收。
- 终末地：协议、默认画质、声音及手柄行为未在本版改变；桥回归通过，不宣称
  这能代替新的实机性能验证。
- 崩铁：新网页登录、保存、重启恢复、续期已联机验证；游戏内登录与游玩未验收。
