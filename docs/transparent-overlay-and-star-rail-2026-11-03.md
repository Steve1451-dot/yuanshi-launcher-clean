# 0.2.104：透明状态窗、精简菜单与崩铁接续

日期：2026-11-03（Asia/Singapore）。原神、终末地按用户本次实机反馈作为可玩基线，
本轮不改已确认的 Xbox 手柄身份、原神位置键位/ZL 体感、媒体协议和软硬解码管线。

## 界面改动

- 实时状态窗取消整块背景，只画文字及偏移阴影。由 13 行收为 8 行：分辨率/解码/
  码率，接收/解码/新帧提交，阶段耗时，关键帧/拥塞丢弃，显示跳帧，音频，UI 帧率/
  间隔，以及“本地耗时并非网络延迟”。不把本地时间伪装成 RTT 或端到端延迟。
- 底层详细统计和自动日志不删减；只是 HUD 不再铺满内部 GPU、轮询等细项。
- 浮球主菜单为六项：画质、帧率、实时状态、手柄映射、更多设置、停止并返回。
  画质/帧率展开后才能改变数值；打开菜单不会意外选择高清或重置已保存的低画质。
- 语言、完整诊断、继续进入、下次解码器放到“更多设置”。所有原操作仍可到达，
  停止仍需二次确认，B 先返回上级，再关闭菜单。
- 设置面板宽 440、高不超过 428（720p），半透明，不再给整个游戏加暗色遮罩。
  触摸命中和绘制共用同一布局；本地控制器编辑器仍使用自己的原布局。
- 原神与终末地共用菜单策略和绘制，保持相同风格。浮窗输入捕获、松键/中立交接
  仍沿用各自已实现的路径。导航模式、保存失败提示等功能不删。

## 同轮追加：归还减号地图键

用户指出减号地图被诊断占用。已移除两个串流视图的 Borealis `BUTTON_BACK`
诊断注册，也修复共享 `ControllerSystemButtons` 无条件清除 Minus 的过滤。
仅删界面快捷键不足以修复，因为旧过滤仍会让线上包缺少 Xbox Back 位。

- 单按减号按标准 Xbox Back（0x20）发给游戏，地图功能遵从云端原始绑定；
  原神无虚拟手柄的键鼠回退发 M 键。已有本地键位表的减号槽保持原值，无需重置表。
- 诊断改为物理 L3+R3 同时按住 800ms，触摸“更多设置 → 完整诊断”也保留。
- 组合键一旦捕获直到两个摇杆都松开，不因松开其中一个就把残留点击漏给游戏。
  打开/关闭及手柄来源切换使用既有中立交接与松键门控，体感同时暂停。
- `+` 与 `-` 的原有长按退出不改；捕获退出组合后，两者都保持本地直到完全松开，
  防止先松一个键就误开远端菜单/地图。单独 `+` 仍发游戏菜单。
- 映射界面的减号从“本地诊断保留”改为“游戏 Back／地图（固定）”，避免旧提示误导。

## 检查出的配置串用问题

此前三个米哈游游戏都读写 `cloudgenshin-stream-settings.txt`。这是源码可确定的
配置串用：调崩铁会改变下次原神的画质/帧率。本轮分离为：

| 游戏 | AppHomePath 内文件 |
|---|---|
| 原神 | `cloudgenshin-stream-settings.txt`（保留旧文件） |
| 崩铁 | `hkrpg-stream-settings.txt` |
| 绝区零 | `nap-stream-settings.txt` |
| 终末地 | `endfield-stream-settings.txt`（原已独立，不改） |

没有给崩铁/绝区零猜测旧共享文件的所有者。各自没有配置时采用既定最低画质/60帧
请求，后续明确选择独立保存。原有原子写入、备份恢复、无效值回退规则保留。

本轮没有发现另一个需要改动它们媒体主链路的确定性新缺陷。已核对退出仍先停止/
等待网络任务，再释放媒体和渲染资源；没有为了精简界面放宽队列或删除恢复逻辑。

稳定基线，不把静态检查和宿主测试描述成零故障保证，也不据此继续改动稳定协议。

## 崩铁：已开始的实际工作与未完成项

本地已有 4.6.0 安卓解包和 JADX 输出，本轮无需重新索取 APK。检查了：

- `reference/android/starrail-cloud-4.6.0-jadx/sources/com/p048mihoyo/combo/interf/IInfoModule.java`：
  设备 ID、设备指纹和渠道接口。
- 同目录树内 `platform/sdk/devicefp/AbstractDeviceUniqueIdentifier.java` 与
  `DeviceFingerprintSharedPreferences.java`：指纹经服务获取/缓存，存在缺失与失败回退。
- `reference/web/sr/combo-web.7d4a7ffa.js`：网页 `getDeviceFingerprint` 调用宿主回调，
  未配置回调则返回空串。不能由安卓的实现推导所有网页终端都必须伪装安卓。

重要边界：现有本地 13 位 FNV 派生指纹并非已经验证的服务返回指纹；“长度正确”
不能证明修复 `1001_2`。旧注释中的因果判断没有独立对照，本轮不据此宣称根因已明。
也不把安卓终端、CPS 和指纹一起改动，以免混淆变量或影响原神。

本轮新增跨 app_id 4/8/12 的生产 SDK 桥离线回归，核对数字 app_id/channel_id、
原始 Combo 元数据、设备 ID 和 CPS 回包，确保崩铁不会误用原神应用编号。

确定修补了一个崩铁可观测性缺口：之前 `1001_2` 固定错误提取也被专用 autotest
trace 开关与前 24 份报告预算一起关闭。现在仅崩铁（app_id=8）在正常版本也识别
游戏上报的这个固定标记，每个桥接实例最多上报一次；原神/绝区零正常路径不变。
扫描仍限制深度 4、128 个节点、字符串 16 KiB，只输出固定事件和数字 1，不保存
消息、账号、设备标识或任何令牌。报告正文和详细 schema 仍只在原 opt-in 路径处理。
有中文解释，并明确该游戏提示不等于串流掉线。

这修好了错误证据缺失，不是 `1001_2` 本身的线上修复。下一项仍是崩铁真实入场的
协议对照：确认新会话是否还报该码，再核对对应官方宿主指纹/登录回包的来源与一致性。
本轮未启动额外账号会话或自动排队，没有占用用户当前实机的云端实例。

## 本轮验证

23 项相关宿主测试通过：菜单策略/透明绘制、状态统计、原控制器编辑/绘制/映射、
体感、中文、每游戏设置、游戏配置、启动输入/派发、SDK 桥与安全报告、生产 RTC
Session，以及终末地桥/设置/实际 XInput 编码。测试传输中的 fake transport error 是故障注入，非在线失败。
包含：全部旧命令仍可达、仅显式停止发停止命令、返回/分页无设置副作用、配置隔离、
65,536 种按键组合、无专用 trace/超过 trace 预算后仍捕获崩铁错误且不泄漏消息。
另覆盖减号/加号单键透传、退出组合两种松键顺序、双摇杆 800ms 只切换一次、
部分松键仍捕获、生产 Session 的 Back 按下/松开、终末地 V1/V2 编码都含 Back 位。

使用实际 NanoVG 绘制调用记录生成了中英文四页预览并检查；预览是合成棋盘背景，
不是模拟器截图或实机帧。透明 HUD 无矩形填充，设置面板无全屏遮罩，保存/恢复栈平衡。
完整 Switch 构建和发布文件校验结果记录在本版发布目录；本轮不声称在线/实机重新验收。
