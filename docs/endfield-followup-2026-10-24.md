## 已完成的关键修复

- 保存的 v1 passport token 可以使用，不需要先补游戏角色 uid。原流程对 binding 服务的授权返回 101，不能据此要求清除账号。
- 按官方 `hg-account-web-sdk.min.js` 的 `User.grantApp` / `U8.API.authByHG`，以旧 passport token 分别取得云应用授权 token 和 U8 游戏票据。exchange 传入这两个临时凭据，原始登录存档保持不变。
- 官方 bundle 的 `et(e,t)` 中空串只是缺省值；调用者 `ex()` 实际先取授权和 U8。已验证直接发送空 U8 会返回 11204。已更正旧协议笔记。
- 实际云 API 响应为 `{code:0,data:...}`；`isSuccess/error` 由网页请求包装器生成。原生解析现兼容两者，保留真实数字错误码，拒绝缺少状态、错误类型及相互矛盾的成功声明。
- 节点按网页实际使用的 `getNodeList(callback,error)` 获取：配置 CDN 上 `/ping/md5(tenantKey+"H5").html` 的 `lines`，主地址失败再用官方备用地址。原来的 ISP 地址/拆分 tenant_params 请求均返回 404。派发 `gameId` 改为原样使用云端返回值，不能从不透明的 tenant_params 截取后六位代替。
- 扫码确认后先保存原始 passport token，角色绑定失败不会丢弃已确认的登录。界面不再把所有会话错误都引导为“清除登录并重扫”。
- 输入增量相对上次成功发送值计算，缓慢摇杆移动可以累计；失败的按钮释放会重试，已成功发送的其他控制不重复发送。
- WeLink 启动消息按顺序确认本地发送成功，失败步骤有间隔地重试，总期限 15 秒。帧率与 app 拦截设置分别重试；SDP 媒体类型不兼容时明确失败。
- 启动、取节点、派发和排队 HTTP 传递取消标志。派发成功与取消同时发生时保留分配 id，保证进入串流之前的退出和异常路径尝试释放分配。
- 分配释放回调随启动结果交给串流视图，在网络线程上处理连接失败、解码器初始化失败、异常与正常退出，不在界面线程等待 HTTP。
- HTTP 传输错误保留安全的 curl/HTTP 数字信息；Endfield 监测脚本补齐阶段与失败事件，避免账号失败被误显示为仍在启动。
- 为 Endfield 的主动发起连接增加 libpeer 可选开关，默认仍为原来的被动模式。该依赖补丁是为了让 SDP 声明与实际 DTLS 角色一致；仅终末地启用，保留证书及指纹校验。`peer_dtls_setup` 验证主动/被动 offer 与实际角色一致，已有三种 answer 角色协商保持通过；接收与循环回归检查通过。
