# 崩铁 1001_2 与设备信息链路（0.2.109 候选）

日期：2026-11-04（Asia/Singapore）。0.2.108 的新扫码保存和续期已成功，但最终
联机仍显示 1001_2。只用此错误码无法断言“网络不好”或“缺某个协议”；必须分别
验证确定的实现差异。0.2.109 当前修补的是一处确认的输入来源缺失，不预先宣称
它能解决游戏错误。

## 上一轮证据

最终 .108 候选 11/11 测速、普通派发、RTC、SDK Init/login 和开场动画可达。
73 秒游戏遥测返回 1001，最新帧明确显示 1001_2。101 秒主动停止，1306 解码帧、
解码错误 0、4138 音频包，无 SDK 入场信号。账号类型、Combo ID、渠道凭据
均存在。不是把测速或扫码失败当作游戏错误。

## 纠正此前不完整的指纹判断

官方本地公开产物 `reference/web/sr/combo-web.7d4a7ffa.js`：

- InfoModule.getDeviceFingerprint 有“无函数则空字符串”的回退。
- 但默认 `ae.device_fp` 已设置 `H().getDeviceFp()` 读取函数；Ct._init 会初始化
  FP SDK。只读 InfoModule 回退而没跟初始化，不能推出“官方始终为空”。
- 模块 971 指定生产 HTTPS 主机 `public-data-api.mihoyo.com`、getExtList/getFp；
  模块 52/795 描述字段配置、请求 nonce、设备元数据和服务结果处理。
- cloud-host 的 setDeviceInfoByCloudGame 还可以覆盖 getter，因此该值的真实来源
  仍须区分，不能用本地 FNV 字符串冒充官方服务值。

## 本版接线

默认不发送。必须经披露后由用户明确同意，并存在严格的独立同意标记，才允许
该功能。普通自动测试开关不算同意，发布包不带同意标记；单次测试许可在结束后
归档，不扩大为永久许可。

只对已同意的崩铁，在 RTC 启动前的网络 worker 请求固定的官方接口，最多两次、每次
10 秒、16 KiB 响应上限，可取消，无重试、跳转、账号、Cookie 或认证请求头。
客户端类型 22 与当前网页登录一致；不改云客户端 19、终端 10、Xbox 输入或媒体。

只提交当前设备 ID、真实原生 User-Agent/Horizon、1280×720 客户端显示面、语言、
触控支持及 SDK 版本。不能取得的浏览器/WebGL/Canvas 信息明确为 unknown，
不伪装 Windows/Android，不伪造自动化或反作弊检查结果。

请求中的 bootstrap device_fp 是官方格式的随机请求 nonce，绝不作为游戏回包。
只有官方 HTTPS 的成功结构和符合长度/字符限制的服务值，才传给 BridgeContext，
供 info_get_device_fingerprint 原样返回。值不进日志或明文文件。失败退回空值并
记录不可用，不替换成本地散列，不宣称验证通过；风险/人工验证不绕过。

成功与请求阶段只留固定数字。获取成功、传到 getter、游戏是否入场是三件不同
的事，监控不得把第一项当作最后一项。

## 测试

合成传输测试覆盖成功、HTTP/网络失败、验证要求、取消、配置拒绝、坏字段、
畸形/缺失值、超长响应和不同游戏隔离。检查没有账号/Cookie/令牌请求字段，
失败没有随机/本地 fallback；桥测试验证服务值到正确 index 的返回及无值/坏值
回退。监控检查“有指纹”不是入场证明。

完整 NRO 及后续增量构建通过。首次外发测试被安全审核阻止后，未绕过或换方法
发送；加入默认关闭的明确同意检查，用户随后明确批准该单次测试，才启动对照。

报告：根目录 `outputs/star-rail-online-20261104/official-device-fp-consented-109`。
NRO SHA-256：`CA495E8174633F60F676B98D028971EA3FE256D6337C44F1607D00E679B2E6B6`。

真实结果：`SDK_DEVICE_FP_STAGE=2`、`SDK_DEVICE_FP_SERVICE_READY=1`、
`GAME_SDK_DEVICE_FINGERPRINT_PRESENT=1`。这分别证明官方服务返回和实际游戏 getter
取到了非空值，日志没有任何值原文。游戏仍返回 1001，当前帧仍显示 1001_2。
127 秒主动停止，3207 解码帧、解码错误 0、5630 音频包，无 SDK 入场信号。

结论：原生没有接入真实指纹来源的缺项已补，但空指纹不是该错误的完整解释；
不能把 0.2.109 称作 1001_2 修复版，也不能因此认定是用户网络问题。

结束后已关闭所拥有的模拟器，归档单次同意及自动测试标记，恢复原隔离 SD/CPU
配置。新网页登录仍保留在测试专用 SD 的加密 vault 内，未输出、导出或放入包。

补充静态核对：Android MiHoYoWebview 的全局 User-Agent 来自真实 WebView，
自动测试分支可返回空；本次游戏确会请求 webview/get_global_user_agent 等宿主
功能。当前 H5 桥对未注册模块返回缺方法对象。仅有 Android 实现不能证明 H5
宿主也必须按相同结构返回，不直接填造 Android UA 或把该差异断言为根因。
