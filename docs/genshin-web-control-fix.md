# 原神 0.2.24：独立控制通道修复

## 这次日志说明了什么

用户提供的 0.2.23 安全日志已通过登录、排队、派发、游戏授权和
DTLS-SRTP。视频为 1280×720，累计解码 711 帧、零解码错误，音频
也有收到。之后 `RTC_SCTP_ASSOCIATION_TIMEOUT` 在媒体连接约 15 秒后
触发，客户端停止串流；不是二维码或视频解码器初始化失败。

服务器返回的 `GAME_CONFIG_WEBCTRL=2` 是关键。仓库外已有的官方公共
网页 SDK `reference/web/ys/cg-sdk.c4be3733.js` 中，
`onSignalingHandshake` 在控制类型 1/2 时创建独立的 GameControlChannel，
先尝试 WebTransport，并明确支持回退至 WebSocket。
原生实现此前忽略此握手及派发控制地址，始终等待 RTC SCTP/DCEP。

## 实现范围

- 根据实际连上的信令服务器索引选择对应派发控制地址；控制列表较短时
  按官方规则使用同一地址族的首个控制地址。不猜地址，也不把另一个
  游戏服务器的会话当作可互换的认证。
- 从信令类型 3 的 JSON 读取非零 uint32 `session_id`，仅用于本次
  内存中的连接。兼容握手早于或晚于游戏授权；停止/重试时清除旧会话。
- 按官方 WebSocket 回退流程，将 HTTPS 控制地址转换为 WSS，添加
  `sessionId` 查询参数，保留证书和 WebSocket Upgrade 验证。
- 控制帧前缀 0，游戏帧前缀 1；包体沿用已有 proto.msg Packet 封装。
  实现 1250 Sync → 1251 SyncAck → 1252 Ack，随后每 2 秒发送 1253 Ping，
  用 1254 Pong 保活。同步等待 15 秒，连续超过 5 秒没有 Pong 明确失败。
- 类型 1/2 的输入 20010 和游戏心跳 20029 走该通道；输入仍要求 RTC
  媒体连接完成。不再错误地等待 SCTP 15 秒，但不会无限隐藏控制错误。
  其他类型保留原 SCTP/DCEP 就绪、超时与断开检查。
- 保留现有 SDP 媒体布局及视频/音频路径。没有修改解码器、登录存档、
  终末地认证、图像资源，也未引入 Android 桥接或电脑转发。
- 安全日志增加独立连接、HTTP 状态、传输返回码、同步就绪与具体失败
  阶段；提供中文。日志不包含会话编号、地址、Cookie、令牌或二维码。

## 离线测试

`scripts/test-mihoyo-host.ps1` 中的 `mihoyo_web_control_channel` 使用
测试专用假传输验证字节格式、会话校验、同步和保活、超时、断开、取消、
不安全地址及 TLS 失败。`mihoyo_rtc_session` 覆盖类型 1/2、握手顺序、
备用信令/控制服务器配对、无 SCTP 关联时持续超过旧的 15 秒截止时间、
输入/心跳实际路由、早于媒体的控制就绪、停止清理及旧会话不复用。
测试时间由模拟时钟推进，不占用账号、不排真实队列。

2026-10-18 检查结果：15 组相关宿主回归测试全部通过（协议、会话路由、
SCTP 策略、派发解析、SDP、输入、界面策略、中文安全日志及 WebSocket）。
最终源码已使用 devkitA64/libnx 成功交叉编译为 NRO；原生入口开关为 ON，
NRO 内嵌标题为 CloudGenshin-NX alpha，版本为 0.2.24。交付 NRO/ELF
与最终构建输出 SHA-256 一致。没有进行在线排队、扣费或真机操作。

## 真机复测

1. 替换 NRO，保留 SD 卡原有 `cloudgenshin-login.key` 和 `.vault`，
   不删除 SwitchNOW 数据目录。入口应显示 0.2.24。
2. 选择原神、开始排队。账号存档仍有效时沿用已有自动登录流程。
3. 日志应依次出现独立控制连接、HTTP 101、等待确认、
   `CONTROL_WSS_READY`（独立控制通道已就绪），以及
   `CONTROL_HEARTBEAT_STARTED`。同时视频解码计数应持续增长。
4. 至少观察 30 秒并测试按键。若停在游戏启动界面，可从 L+R 设置面板
   使用现有“继续 / 手动点击一次”。不能把发送成功当作远端确实响应。
5. 若仍失败，提供新的 `cloudgenshin-safe.log` 或中文日志即可。
   重点看 `CONTROL_WSS_...` 的具体阶段；不需要提供登录密钥/凭据。

本次离线测试和交叉编译不能代替真实 Switch 的在线验证，也不能证明
游戏已经可完整游玩或所有网络下都稳定。以设备实际画面和输入反馈为准。
